# Ours 同步服务

这是为将来的 Ours 手机／电脑网页准备的独立同步 API。它保存一份双人空间的完整 JSON 快照，并用修订号防止并发写入时静默覆盖；照片、视频等媒体通过独立的 SHA-256 内容寻址接口保存。**网页已提供可选接入，默认关闭；本服务不会读取、修改或写入原有小程序的数据。**

服务使用 Node.js 22 内置模块，无 npm 依赖。当前实现依赖 POSIX 文件权限，以及支持硬链接、原子重命名和目录同步的本地文件系统；已在 macOS 本地验证，Windows 原生环境不受支持。当前只提供本机 HTTP 服务，没有内置 HTTPS、账号系统或冲突合并。

## 本地启动

在本目录执行以下命令。第一行用系统随机数在当前 shell 中生成一个新的 32 字节共享凭证，命令不会输出凭证值；重启服务或换设备时必须通过安全渠道继续使用同一个凭证。这里没有可直接使用的固定令牌。

```sh
export OURS_SYNC_TOKEN="$(node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))")"
export OURS_SYNC_ALLOWED_ORIGINS="http://127.0.0.1:4173"
node server.js
```

默认仅监听 `127.0.0.1:8787`。启动前必须设置 `OURS_SYNC_TOKEN`：它必须是 **32 个密码学安全随机字节**的无填充 base64url 编码（43 个字符）。服务会检查编码和明显过弱的值，但无法证明人为选择的字符串具有随机性，因此务必使用安全随机数生成。服务不打印凭证；不要把凭证放进源码、Git、URL、请求日志、示例、网页静态资源或真实数据的测试夹具。

配置项：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `OURS_SYNC_TOKEN` | 无，必填 | 双方共享的随机 Bearer 凭证，具有完整读写权限 |
| `OURS_SYNC_PORT` | `8787` | 本机端口，`0` 可供测试时申请临时端口 |
| `OURS_SYNC_ALLOWED_ORIGINS` | 空 | 浏览器来源白名单，多个完整来源用逗号分隔，例如 `http://127.0.0.1:4173` |
| `OURS_SYNC_DATA_SLOT` | `default` | 存储子目录名，仅允许 1–64 个英文字母、数字、下划线或连字符；它不是用户身份或隔离机制 |

浏览器请求携带 `Origin` 时，该来源必须与白名单完全一致，包括协议、主机和端口；不要在配置中加路径或末尾斜杠。使用同源反向代理时，也应配置网页的完整来源，因为浏览器可能发送 `Origin`。不带 `Origin` 的非浏览器客户端仍可访问，但仍必须鉴权。不支持通配符、`null` 来源或直接打开 `file://` 网页；本地网页请通过本地 HTTP 开发服务器访问。白名单只控制浏览器跨域访问，不能替代凭证。

## API 合约

快照路径为 `/v1/snapshot`，媒体路径为 `/v1/media/<sha256>`；查询参数和其他路径均不可用于指定数据位置。所有数据请求都必须携带：

```text
Authorization: Bearer <通过安全设置获取的共享凭证>
```

仅 `GET`、`PUT` 可读写数据。快照的 `ETag` 值包含 HTTP 双引号，客户端应原样保存和回传，而不是自行添加或移除引号；媒体接口使用单独的内容摘要 ETag。

### 读取快照

`GET /v1/snapshot`

成功返回 `200`，响应头包括 `ETag: "<revision>"` 和 `Cache-Control: no-store`，响应体：

```json
{"revision":"0","snapshot":null}
```

`revision` 是不透明字符串。首次使用、还没有成功写入时，修订号为 `0`，快照为 `null`；成功写入 JSON `null` 后也会得到新的非零修订号。之后返回最近一次已提交的 JSON 值，`snapshot` 可以是对象、数组、字符串、数字、布尔值或 `null`。服务保留提交的 JSON 文本；客户端自己的 JSON 解析器可能会改变超出其数值精度范围的数字。

### 条件写入快照

`PUT /v1/snapshot`

请求体直接是**完整的新 JSON 快照**，不是局部补丁，也不是带 `revision` 的包装对象。请求必须带：

```text
Content-Type: application/json
If-Match: <上次读取或成功写入时响应的完整 ETag>
```

只接受单个强 ETag，不接受 `*`、弱 ETag 或列表。服务在串行化写入过程中核对修订号；匹配时原子持久化，返回 `200`、新的 `ETag` 以及与读取相同格式的 `{revision, snapshot}` 响应。首次写入也必须先读取 `ETag: "0"` 并回传。

修订号不匹配时返回 `412`，响应头 `ETag` 为当前修订号，响应体为 `{"error":"revision_conflict","revision":"<当前修订号>"}`；**不会应用该次写入**。缺少 `If-Match` 返回 `428`；格式错误返回 `400`。不要把冲突响应视为可以直接覆盖远端的许可。

服务返回的应用层错误为 JSON：`{"error":"<代码>"}`。常见状态包括 `400`（无效请求或 JSON）、`401`（凭证无效）、`403`（来源或预检不允许）、`404`（路径不存在）、`405`（方法不允许）、`413`（请求过大）、`415`（媒体类型或编码不支持）、`428`（缺少条件）、`500`（存储错误）、`503`（写入繁忙，可稍后重试）。HTTP 解析器拒绝格式错误的连接或超时请求时，也可能直接返回非 JSON 错误。

### 上传媒体

`PUT /v1/media/<sha256>`

路径中的 `<sha256>` 必须是请求体原始字节的 64 位十六进制 SHA-256 摘要，接受大小写，服务统一以小写保存和返回；路径不得包含查询参数、转义字符或其他段。请求体是文件的原始二进制字节，不是 JSON、base64 或 multipart。可设置 `Content-Type: application/octet-stream`；服务不保存或依赖请求的媒体类型，不接受 `Content-Encoding`。每个文件最多 **104,857,600 字节（100 MiB）**，包含恰好 100 MiB 和空文件；无论使用 `Content-Length` 还是分块传输都执行上限检查。

服务逐块计算摘要并写入私有临时文件，只有收到完整请求且摘要匹配后才原子提交，不会覆盖已有文件。首次提交成功返回 `201`，已存在同一内容时验证请求体和已有文件后返回 `200`；两种成功响应体均为空，并带 `ETag: "<小写 sha256>"`。并发上传同一内容时也只创建一个文件，其余有效请求按重复上传成功返回。请求体摘要不匹配返回 `400`、`{"error":"hash_mismatch"}`；超限返回 `413`、`{"error":"payload_too_large"}`；已有文件损坏或权限不安全时返回 `500`，不会覆盖它。中途断开不会提交不完整文件。超时或 `5xx` 后提交结果可能未知：可以用相同摘要和相同内容安全重试，或下载并核对内容。

### 下载媒体

`GET /v1/media/<sha256>`

成功返回 `200`、原始文件字节、`Content-Length` 和 `ETag: "<小写 sha256>"`；文件不存在返回 `404`。响应固定为 `Content-Type: application/octet-stream`、`Content-Disposition: attachment`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: no-store`，不会根据文件内容推断或执行类型。客户端可以在快照中单独保存原始 MIME 类型等元数据，下载后自行校验 SHA-256 并按需要显示。服务不提供目录列表、删除接口、分段下载或断点续传。

### 跨域预检

允许来源发出的浏览器 CORS 预检可在没有凭证时访问 `OPTIONS /v1/snapshot` 和 `OPTIONS /v1/media/<sha256>`，只允许预检 `GET`、`PUT` 以及 `Authorization`、`Content-Type`、`If-Match` 请求头，不返回数据。实际读取和写入仍必须鉴权；允许的跨域响应会暴露 `ETag`。

## 离线记录与冲突处理

网页需自己持久化本地记录、待同步状态和上次同步的基线；本服务不会替网页实现这些功能。建议的同步过程：

1. 用户在离线或在线时先更新本地记录，不因网络问题丢弃本地修改。
2. 联网后计算并上传尚需同步的媒体；先确认上传成功，再在快照中引用摘要，避免快照指向尚未提交的媒体。另一台设备按摘要下载并核验。快照和媒体不是一个事务，客户端需保留失败重试所需的本地文件与状态。
3. 读取服务器当前快照和 ETag；将远端、上次同步基线和当前本地记录进行适合业务的合并，再以读到的 ETag 条件写入完整快照。
4. 收到 `412` 时保留本地修改，重新读取、合并并由客户端决定是否重试或请用户处理冲突。两台设备都写入同一个旧版本时，最多一台成功。
5. 超时、断线或 `5xx` 后，写入结果可能未知：文件可能已经原子提交，但响应或目录同步失败。先重新读取并核对、合并，再决定如何重试；不要假定远端完全没有变化。
6. 仅在服务确认写入成功，并且客户端本地提交成功后，更新本地同步基线。当前网页的删除和冲突策略见 [`web/README.md`](../web/README.md)；服务端只负责条件写入，不理解记录内容。

## 持久化、限制与部署注意事项

- 快照默认位于本目录 `data/default/snapshot.json`，媒体位于 `data/default/media/<小写 sha256>`，`data/` 整体已由本目录 `.gitignore` 排除。启动时创建的目录仅允许所有者访问，文件以所有者读写权限创建；已有目录或快照权限过宽时服务拒绝启动，媒体文件权限不安全时拒绝访问。应持久保存或挂载整个 `data/`，并单独实施受保护的备份和恢复。数据和临时文件为**明文**，服务不提供端到端加密。
- 启动时同步数据目录及其父目录；快照先写入同目录临时文件并同步，再原子重命名并同步目录。媒体先同步同目录私有临时文件，再用不覆盖已有文件的硬链接原子提交并同步目录。启动时如果已有快照损坏或不可读取，服务会拒绝启动，不会静默重置；媒体不在启动时全量校验，下载客户端应自行校验摘要。突然断电的最终持久性依赖文件系统的同步、硬链接和原子重命名语义；请使用支持这些语义的本地文件系统。
- 每个数据目录只允许一个进程持有 `.lock`；不要使用多进程、集群或多个副本共享同一目录。正常停止时锁会移除；进程被强制终止可能留下锁。只有确认所有使用该目录的服务进程已经停止后，才能检查并移除 `data/<slot>/.lock` 再启动；不要依赖锁文件里的 PID 单独判断进程是否仍是原进程。异常退出也可能留下 `.snapshot-*.tmp` 明文文件，确认服务停止并妥善处理后可清理；媒体上传临时文件在正常中断时清理，强制退出遗留的临时文件在获得数据槽锁后于下次启动时清理。
- 快照本体上限为 **16,777,216 字节（16 MiB）**，包含恰好 16 MiB，按 UTF-8 编码后的字节计；`Content-Length` 和分块上传都会受限，超限返回 `413` 和 `{"error":"payload_too_large"}`。只接受未压缩的 `application/json`，可选 `charset=utf-8`；媒体散列、元数据和嵌入快照的 base64 均计入该上限。成功的 GET 和 PUT 响应在快照本体外还包含 `revision` 等 JSON 包装：非初始修订号的包装为 63 字节，因此响应体最多 **16,777,279 字节（16 MiB + 63 字节）**；客户端的响应读取限制应留出这些额外字节。媒体单文件上限为 **100 MiB**，上传和下载均流式处理。
- 快照和媒体合计最多同时处理 4 个写请求；成功的快照写入会一直占用名额，直到服务端写完响应或连接关闭，避免慢速读取的写入响应积累大量快照。忙时返回 `503`、`{"error":"server_busy"}` 和 `Retry-After: 1`。允许的跨域网页可读取错误体，但 CORS 只暴露 `ETag`，因此不能读取 `Retry-After`；可对 `server_busy` 按一秒退避重试。该限制不涵盖读取，也不是进程总内存的硬上限。请求头最多 8 KiB、最多 64 个头，最多 64 个连接；快照请求从开始处理到响应写完最多 15 秒，媒体请求最多 60 分钟，约 60–65 秒套接字的应用层收发字节数没有变化也会断开。一个连接只允许一个尚未完成的请求，重叠的 HTTP/1.1 管线请求会导致连接关闭；按顺序复用连接不受影响。这些限制不替代面向公网的访问控制、限流和监控。
- 服务**不提供自动垃圾回收**：即使快照不再引用某个已提交媒体，文件仍会占用磁盘空间。清理遗留上传临时文件不等同于删除已提交媒体；如需删除或回收媒体，必须在确认所有设备、快照和备份都不再需要后，由维护者自行规划并执行。快照不校验业务结构、不自动合并、不保留历史版本，也不提供增量同步或自动备份。
- 对外使用时，必须在可信反向代理处配置 **HTTPS**，并继续让本服务仅监听本机；代理需正确转发 `Authorization`、`If-Match` 和 `ETag`，允许 100 MiB 请求体及足够长的传输时间，禁止缓存快照和媒体，不记录凭证或请求体，并配置适当的限流及访问控制。凭证是共享读写权限，任何持有者都能读取或替换整个空间；泄露后需安全轮换服务端和双方设备的凭证。
- 凭证应由网页运行时通过安全方式配置，切勿硬编码进公开的前端构建产物。网页中运行的恶意脚本或设备本身被入侵时，凭证和明文记录可能泄露；HTTPS 只保护传输。恢复旧备份后，客户端应重新读取和合并，不能假设恢复期间的同步历史仍然存在。

## 测试

```sh
node --test
```

测试只生成随机临时凭证、合成 JSON 和二进制数据，使用本机回环连接与 `data/` 内的临时子目录，结束后删除测试数据。测试涵盖快照兼容性、16 MiB 精确边界和超限、重启后读取、快照与媒体共享的 4 个并发写入名额、媒体上传下载、摘要错误、鉴权、CORS、路径和符号链接、权限、重复与并发、媒体 100 MiB 精确边界和超限、慢速传输、中断清理、持久化及强制重启；也覆盖快照冲突、JSON 校验和慢速连接。不会模拟真实断电，不会连接线上服务或使用真实用户数据。
