# Ours 网页版

独立的响应式官网与本地优先回忆册，不依赖现有小程序、云函数或管理台。默认不连接任何服务；可自行配置独立同步服务和共享凭证。当前没有已部署的同步服务、登录或原生应用安装包。

## 本地运行与构建

需要 Node.js 20 或更新版本，不需要安装 npm 依赖：

```sh
cd web
npm run dev
# 打开 http://127.0.0.1:4173/

npm run build
npm run verify
npm run preview
```

`npm run build` 检查 JavaScript 语法和图标后，将静态文件复制到 `web/dist/`。该目录可交给未来选定的静态网站服务。`PORT=其他端口 npm run dev` 可以更换端口。

小程序导入的合成数据回归（需安装 `cloudfunctions/ours` 已声明的 `archiver` 依赖）：

```sh
node --test tests/wx-import.test.mjs tests/wx-prepare.test.mjs
node tests/wx-app.browser.mjs
```

浏览器测试需要 Node.js 22+ 和本机 Chrome/Chromium；可用 `CHROME_PATH` 指定浏览器。测试使用隔离的临时浏览器配置、模拟云媒体和真实 `zipBackupPart` 生成分卷，不读取实际备份或连接线上服务。它覆盖预览、取消、缺卷、导入及重复导入、媒体显示、并发 ID、模拟配额异常回滚、数量和备份目录上限，以及 `.ours` 导出和恢复。

不要直接双击 `index.html`：模块、IndexedDB 和 Service Worker 需要通过 HTTP 服务访问；安装与离线能力通常需要 HTTPS，localhost 是浏览器允许的本地开发例外。部署到子路径时，保留目录结构，并让该路径内的 `index.html`、`service-worker.js`、模块、manifest 和 assets 均可访问；Service Worker 只控制其所在目录。

每次联网打开或刷新时，网页会向服务器重新验证页面和静态资源，成功取得的版本会用于之后的离线访问；断网或服务器暂时返回 5xx 时，会回退到已缓存的内容。构建会根据资源内容自动生成版本号，更新 HTML 中的资源地址、模块依赖和 Service Worker 缓存；正常发布不需要手动修改缓存版本。请完整部署 `dist/`，建议为 HTML 和 `service-worker.js` 设置 `Cache-Control: no-cache`；CDN 的资源缓存键应包含 `v` 参数，并在发布后刷新仍保留旧文件的 CDN 缓存。旧版 v1 安装会自动切换到新版缓存；离线使用新版本前需等待新版 Service Worker 安装并接管页面。更新不会清除 IndexedDB 或本机记录。

浏览器更新回归可运行 `npm run verify:update`。该测试需要 Python 3.9 或更新版本、Python Playwright 和 Chromium（也可设置 `CHROME_PATH` 使用已安装的 Chrome/Chromium）；它在临时目录中构建多个版本，验证根路径、子路径、旧版迁移、联网更新、离线与 5xx 回退，以及 IndexedDB 中记录和图片的完整性，并检查同步模块的离线加载。

同步界面和元数据损坏后的备份恢复回归可运行 `node --test tests/sync-app.browser.mjs tests/metadata-recovery.browser.mjs`，需要 Node Playwright 和 Chrome/Chromium；若 Playwright 不在此目录的依赖搜索路径中，可通过 `OURS_TEST_PLAYWRIGHT` 指定其 `index.mjs` 绝对路径，并通过 `CHROME_PATH` 指定浏览器。测试使用隔离的临时浏览器数据、临时复制的本机同步服务、随机凭证和合成记录，覆盖两端同步、媒体、离线、冲突、数据库升级、同步中的修改和导入备份；不会使用真实账号或线上服务。运行 `npm run build` 后，还可用相同的浏览器参数运行 `node --test tests/sync-pwa.browser.mjs`，验证构建产物对同步模块的预缓存与离线读写。

## 可选的设备间同步

默认关闭同步，也没有预设服务地址。自行准备符合 [`ours-sync` 接口](../ours-sync/README.md)的服务，按该文档生成 32 字节随机共享凭证、配置浏览器来源白名单；对外使用时须由可信反向代理提供 HTTPS。正式服务尚未部署，保存设置并不表示已连接。

在需要同步的每个设备打开「同步设置」，输入同一个服务的 HTTPS 来源和共享凭证并启用；仅 `localhost`、`127.0.0.1`、`[::1]` 的 HTTP 地址可用于本机开发。地址不得带路径、用户名、密码或参数。凭证保存在浏览器 IndexedDB 中，由网页请求的授权头发送；它具有整个空间的读写权限，未经端到端加密，需安全传递并保护浏览器和服务器。服务端数据和导出的备份也不是端到端加密的。不同浏览器或部分主屏幕应用各有独立存储，需要分别设置。

联网后保存、编辑或导入会安排同步，页面打开、定时后台刷新、回到前台和恢复联网时也会检查；浏览器可能限制或暂停后台页面，页面关闭时也不会同步。两端内容均无变化时的例行检查不会重复上传媒体；内容有变化或恢复待处理请求时，仍可能重新上传已有媒体，在移动网络下可能消耗较多流量。断网时仍可本地使用。状态中的「上次同步成功」只表示那一次服务和本机提交成功，之后其他设备仍可能有新修改。图片、视频和导入的小程序回忆都会参与同步，小程序云数据不会被写回。同步引擎当前限制快照不超过 16 MiB、最多 10000 条记录，每个媒体最多 100 MiB；超过限制时同步会暂停，本机记录仍在。网络或存储失败可能留下待处理日志，用于核对不确定的远端提交；不要清除浏览器数据，也不要手动修改该日志。

对方未修改该记录或两端都删除时，删除会参与同步；删除与对方编辑同一记录、双方同时编辑、同步历史变化或待处理期间本机发生变更时可能产生冲突。同步不保存删除历史，从旧备份重新导入已删除的记录后，它可能被当成新记录再次同步。发生冲突时，网页会保留现状并暂停，提供备份入口，但目前没有冲突解决界面。请先在两端分别导出备份并人工核对；即使本机已经没有回忆，也可导出空备份，记录当前内容为空。`.ours` 只包含当前回忆和媒体，不包含同步设置、历史、待处理日志或已经删除的内容，不能用它恢复这些信息；不要清除浏览器数据或更换服务来绕过冲突。已存在同步历史或待处理日志时，网页不允许直接切换服务地址；可以暂停同步或更换同一服务的凭证，暂停不会清除历史或日志。更换服务地址时需明确重新输入凭证，避免将旧服务的凭证发给新地址。正在编辑的草稿若遇到本机数据变化，需重新编辑或另存为新回忆，避免覆盖新内容。

同步依赖安全上下文和浏览器 Web Locks 来跨标签串行化；不支持或无法获得安全锁时会暂停同步，但本地记录和备份仍可使用。Safari 及 iPhone/iPad 的实际设备行为尚未验证，请以设备上的状态为准，不应假定同步可用。

## 使用与数据边界

- 在首页选择「开始记录」，可以创建、搜索、编辑和删除回忆，填写日期、文字并添加图片或视频。每条最多 9 个媒体文件，每个最多 100 MB；浏览器剩余空间可能更少。能否显示特定图片和播放特定视频取决于浏览器支持的格式。
- 数据先保存在当前浏览器的 IndexedDB；只有自行启用并配置可用服务后才会尝试同步。不同设备、不同浏览器，以及部分手机上的主屏幕应用和普通浏览器可能使用不同的存储；可使用备份手动转移。浏览器清除网站数据、存储被回收、设备损坏均可能造成丢失。
- 「备份与导入」可导出 `.ours` 文件，包含网页记录的文字、日期及媒体字节。同步元数据损坏而回忆存储仍可读取时，也可以导出当前回忆；备份不包含同步历史或待处理日志，仍需保留原浏览器数据。备份未加密，请妥善保管；导入会校验目录、长度和媒体 CRC32，并在一个数据库事务中合并，已有相同 ID 的记录会跳过而不会覆盖。CRC32 用于发现意外损坏，不提供加密或防篡改。建议定期备份并另存一份。
- 可在「备份与导入」中一次选择同次小程序备份的全部 ZIP 分卷，先只读检查并预览，再自行确认导入。请保留原始备份；网页不会写回小程序。缺卷、损坏或解析器限制会阻止整包导入；取消和事务失败不会留下半套新记录。解析器限制见 `wx-import.js` 的 `WX_IMPORT_LIMITS`（例如最多 128 卷、ZIP 总计 1.5 GiB、媒体总计 1 GiB）。
- 仅普通回忆 `moments` 中可识别为 `kind: post` 的文字、发生日期、图片和视频可导入；仅支持 JPEG、PNG、GIF、WebP、MP4、MOV、WebM，文件头检查不能证明内容真实或可播放。视频封面作为图片保留，若与图片列表中的文件相同则不重复导入，可能和视频画面重复。含语音或实况照片的回忆、来源或原 ID 不明确、日期不可识别、媒体不安全、超过 9 文件或单个超过 100 MiB 的回忆会整条跳过，预览列明原因。若记录包含小程序写入的媒体数量或大小统计，统计须与引用和 ZIP 文件一致；不一致可能由旧统计或媒体变化造成，也会整条跳过。旧回忆没有发生日期时，只有创建时间有效才按小程序的 UTC+8 日期补齐。
- 评论、点赞、纪念日、打卡、便签、吐槽、地点、作者以及其他小程序专有信息不导入。小程序 ZIP 本身没有空间 ID，网页从每条原始记录的 `coupleId` 与 `_id` 生成稳定 ID；来源缺失或不同记录的空间标识矛盾时不会猜测。同 ID 再导入只跳过，不覆盖网页编辑；这些 ID 也由 `.ours` 备份保留。为确保仍能导出网页备份，小程序导入后记录总数不得超过 10000。
- 导入会同时检查网页版最多 10000 条记录与 `.ours` 备份目录 8 MiB 的上限；确认时会在事务内重新检查，其他页面同时修改时也不会覆盖已有 ID。不同来源如果复用了同一 `coupleId` 和原始 `_id`，旧 ZIP 没有额外环境标识，网页无法区分，会将其视为同一条回忆。
- 旧小程序备份没有可靠的跨卷备份标识或可信媒体哈希：即使卷数、清单和 CRC-32 检查通过，也无法证明分卷来自同一次备份或媒体真实、未被替换。解析器只识别已知媒体字段，未知字段可能还有无法识别的引用；已知媒体引用未打包、备份损坏、缺卷或超出解析器限制时，会拒绝整个备份而不会导入部分记录。
- 首次联网打开后，浏览器需要完成 Service Worker 安装和缓存，之后才可离线启动和使用本机数据。清除浏览器数据也会清掉缓存；隐私模式、低存储空间、浏览器策略和平台差异可能限制此能力。
- iPhone/iPad 可在 Safari 的分享菜单中选择「添加到主屏幕」。Android 和桌面端可使用浏览器提供的安装选项；具体支持情况因浏览器而异。此功能安装的是网页，不是原生 App。

## 发布安装包

首页的下载区不写死在 HTML 里，而是读 `releases.json`。清单由 `releases.js` 校验，格式不合格会整份拒绝并在控制台报错——页面宁可退回静态说明，也不显示半真半假的版本信息。校验规则在 `tests/releases.test.mjs` 里有覆盖，不进浏览器也能跑。

```sh
node --test tests/releases.test.mjs
```

每个平台有三种状态：

| 状态 | 含义 | 必填字段 |
| --- | --- | --- |
| `available` | 现在就能用，但不是安装包（目前只有网页版） | `cta.label`、`cta.href` |
| `published` | 有可以下载的安装包 | `downloads`（至少一条） |
| `unpublished` | 还没有可安装的版本 | `note`（写清楚现在能用什么替代） |

一条 `downloads` 记录：

```json
{
  "version": "0.2.0",
  "releasedAt": "2026-11-20",
  "url": "./downloads/Ours-0.2.0-arm64.dmg",
  "file": "Ours-0.2.0-arm64.dmg",
  "bytes": 52428800,
  "sha256": "<64 位小写十六进制>",
  "label": "Apple 芯片",
  "minOS": "macOS 12 或更新",
  "notes": "这一版改了什么。"
}
```

发布一个新版本的步骤：

1. 把安装包放进 `web/downloads/`（构建会整体复制到 `dist/downloads/`）。
2. 用 `shasum -a 256 <文件>` 得到校验和，按上面的格式加一条 `downloads`，把平台状态改成 `published`。
3. 改 `updatedAt`，需要的话往 `changelog` 里加一条更新说明（按版本倒序显示）。
4. 构建并上传 `dist/`。已经部署好的站点也可以只替换根目录的 `releases.json` 和 `downloads/` 里的文件，不必重新构建。

几条刻意的限制：

- 清单不进 Service Worker 预缓存，每次打开都重新取，所以换版本后已经装过网页版的人也能看到新版本。
- `url` 只接受 `./` 相对路径或 `https://`，不允许 `..` 跳出站点目录；`file` 只能是文件名。这是为了防止清单里的笔误变成任意跳转。
- 安装包都没有经过应用商店签名：macOS 首次打开需要在「隐私与安全性」里放行，iOS 侧签名方式尚未确定。清单只描述「有什么可以下载」，不承诺能直接双击安装。
- 下载区读不到 `releases.json` 时会保留 HTML 里的静态说明，并提示「暂时读不到版本清单」，不会假装有版本可下。
